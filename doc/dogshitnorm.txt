1. Introduction                                         *dogshitnorm-intro*

dogshitnorm.nvim is a Neovim plugin for 42-style C projects, with optional
42 Python project initialization. It combines:

- asynchronous `norminette` diagnostics
- safe code actions and quick fixes
- Makefile generation and source syncing
- native 42 header insertion and update
- Python project initialization through an external setup CLI
- header guard, include, define, and prototype helpers
- visual 42 header styling

Open the public docs at:
https://0xveya.github.io/dogshitnorm.nvim/

==============================================================================
2. Requirements                                    *dogshitnorm-requirements*

- Neovim 0.10+
- `norminette` in `$PATH`
- Tree-sitter C parser for the full custom diagnostics
- Python support is optional and requires an external setup CLI configured
  through `python_setup.script` (see |dogshitnorm-makefiles|)

==============================================================================
3. Installation                                    *dogshitnorm-installation*

With `lazy.nvim`:

>lua
{
  "0xveya/dogshitnorm.nvim",
  ft = { "c", "cpp", "make" },
  opts = {
    cmd = { "uv", "tool", "run", "norminette" },
    args = { "--no-colors" },
    norminette_use_gitignore = true,
    active_dirs = { "~/coding/42" },
  },
}
<

Run `:helptags ALL` after local changes if needed.

4. Commands                                          *dogshitnorm-commands*

General:

- `:Norminette`
- `:NormFix`
- `:NormFixAll`
- `:NormLineCounts`
- `:NormLineSavers`

Headers:

- `:Stdheader` inserts or refreshes the native 42 header
- `:StdheaderAll [path]` inserts or refreshes 42 headers recursively under a
  project tree
- `:HeaderToggle` toggles visual header styling
- `:HeaderHide [toggle|on|off]` folds the real header out of the current
  window while keeping it in the file
- `:Protoheader` inserts the selected or current C function prototype into the
  resolved header file
- `:Includesort`
- `:Definesort`
- `:Protosort`

Makefiles:

- `:Makegen`
- `:Makegen python`
- `:Makegen c`
- `:Pyprojectgen`
- `:Makesync`
- `:Makelib [name]`
- `:Makedebug [toggle|on|off]`
- `:Makestatus`

Python project defaults:

>lua
project_type = "auto"
python_dirs = { "*python*", "*py*" }
c_dirs = {}
python_version = "3.10"
python_package = nil
python_setup = {
  script = nil,        -- path to the external setup CLI (required)
  python = "python3",
  test_file = nil,     -- optional test suite copied into tests/
  max_line_len = 100,
  toolchain = "uv",
  checks = { "mypy", "ruff", "pytest" },
  debug = false,
}
norm_exclude_dirs = {}
<

Change `python_version` when a subject requires a different Python version.
Change `python_package` when the import package should differ from the folder
name. `norm_exclude_dirs` lists directories where norm diagnostics are
suppressed entirely (useful for non-C projects inside `active_dirs`).

6. Makefiles                                        *dogshitnorm-makefiles*

Generated Makefiles include:

For C projects:

- explicit `SRCS`
- objects and dependency files kept out of the tree in `OBJ_DIR = obj`
  (nested source folders are mirrored via `mkdir -p`)
- objects depend on the Makefile, so editing it triggers a rebuild
- parallel builds by default with `JOBS ?= $(shell nproc)` and
  `MAKEFLAGS += -j $(JOBS) -l $(JOBS)`
- dependency files with `CPPFLAGS = -MMD -MP`
- `DEPS` and `-include $(DEPS)`
- `DEBUG ?= 0`
- auto-detected `libft` and `ft_printf`/`libprintf` recursive rules when present
- `:Makelib` conversion for static libraries
- `:Makedebug` to flip debug mode
- `:Makestatus` to report binary/library and debug/deps state

Auto-generation only ever fills empty (or header-only) Makefiles. A Makefile
that has a body belongs to you: opening it never re-templates or rewrites it.
Source syncing still updates the `SRCS` block when C files are created,
renamed, or deleted on disk (saves and oil.nvim actions), and the explicit
`:Makegen`/`:Makesync` commands still sync structure on demand.

For Python projects, initialization is delegated to an external setup CLI
(`python_setup.script`). `:Pyprojectgen` collects the CLI flags (package name,
line length, toolchain, checks, debug) through |vim.ui.input()| and
|vim.ui.select()| prompts, runs the CLI, copies the configured
`python_setup.test_file` into `tests/` with imports rewritten to the chosen
package, and writes supporting files (`.gitignore`, `.editorconfig`,
`.python-version`) when missing. Initialization refuses to run when a
non-empty `pyproject.toml` already exists.

`project_type = "auto"` detects Python from markers such as `pyproject.toml`,
`.python-version`, `uv.lock`, top-level `*.py`, and folder globs like
`*python*` and `*py*`. Use `:Makegen python` or `:Makegen c` to force one
kind; `:Makegen python` on an empty Makefile starts the same interactive
initialization as `:Pyprojectgen`.

Python files and Python-project Makefiles do not get 42 headers and do not run
norminette. C-only commands such as `:Makesync`, `:Makelib`, and `:Makedebug`
notify instead of rewriting Python Makefiles.

`makefile_exclude_dirs` defaults to ignoring:

- `.git`
- `.jj`
- `tests`
- `test`
- `build`
- `libft`
- `libprintf`

==============================================================================
7. Headers                                            *dogshitnorm-headers*

dogshitnorm.nvim can insert the standard 42 header for C-like files and C
Makefiles without depending on `42Paris/42header`.

Identity is resolved from, in order:

1. `opts.header_user` / `opts.header_email`
2. `vim.g.user42` / `vim.g.mail42`
3. environment variables

The `Updated:` line is refreshed on save when `update_42_header = true`.

The visual styling previously provided by `fancy-header.nvim` is included in
dogshitnorm itself and toggled with `:HeaderToggle`.

If `header_hide_enabled = true`, the current window folds the header out of
the way while keeping it in the file for norminette, and buffer-local `gg`
jumps to the first non-header line in that view. With
`header_line_number_offset = true`, displayed line numbers start at `1` on the
first non-header line instead of counting the 42 header.
